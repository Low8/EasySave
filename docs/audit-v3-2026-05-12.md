### B. Parallélisme — v3

| Point | Statut | Détail |
|---|---|---|
| Jobs parallèles (`Task.WhenAll`) | ✅ OK | `BackupService.RunRange` : `await Task.WhenAll(tasks)` |
| Workers parallèles dans un job | ✅ OK | `BackupJob.Execute` : 3 workers concurrents via `Channel<string>` |
| **`maxDegree` hardcodé à 3** | 🔴 CRITIQUE | `BackupJob.cs:41` — `var maxDegree = 3;` n'est pas lu depuis `AppSettings`. À externaliser dans `AppSettings.MaxParallelWorkersPerJob` |
| `SemaphoreSlim(1,1)` pour gros fichiers | ✅ OK | `TransferCoordinator._largeFileSemaphore` |
| Seuil KB configurable | ✅ OK | `AppSettings.MaxFileSizeForParallelTransferKb` (défaut 1000) |
| `CancellationToken` propagé jusqu'à IO | ✅ OK | `PausableFileCopy.Copy` appelle `ct.ThrowIfCancellationRequested()` par chunk |
| Pause via `ManualResetEventSlim` | ✅ OK | `_pauseEvent.Wait(ct)` appelé avant chaque transfert de fichier |
| Stop immédiat via CT | ✅ OK | `OperationCanceledException` remonte jusqu'à `BackupService.RunJob` catch |
| **`_pauseEvents` dict non thread-safe** | 🔴 CRITIQUE | `BackupService.GetPauseEvent(int)` lit/écrit dans `Dictionary<int, ManualResetEventSlim>` sans lock. Race possible si deux appels `RunJob` avec le même index se chevauchent. Remplacer par `ConcurrentDictionary` |
| **`Notify()` non thread-safe** | 🔴 CRITIQUE | `BackupService.Notify` itère `_observers` (List<>) sans lock. Plusieurs jobs parallèles appellent `Notify` simultanément depuis leurs threads. Race condition. Utiliser `ImmutableArray` ou un `lock` |
| **`WaitForPauseAsync` bloque des thread-pool threads** | ⚠️ MAJEURE | `Task.Run(() => pauseEvent.Wait(ct), ct)` est appelé jusqu'à 3 fois par fichier par job. Sous forte charge (N jobs × 3 workers), cela peut saturer le thread pool. Remplacer par `ManualResetEventSlim` avec polling async ou un `SemaphoreSlim` |
| `BackupJob` ne référence pas `EasyLogger` directement | ✅ OK | Passe par `IEncryptionService` et `ITransferCoordinator` uniquement |

### C. Priority file management

| Point | Statut | Détail |
|---|---|---|
| Extensions prioritaires configurables | ✅ OK | `AppSettings.PriorityExtensions` (List<string>) |
| Blocage non-prioritaires si prioritaires en attente | ✅ OK | `TransferCoordinator.WaitAsync` check `_priorityFileCount > 0` |
| Thread-safety du compteur | ✅ OK | `_priorityFileCount` protégé par `lock (_lock)` |
| **TOCTOU sur `_nonPriorityWaiters`** | ⚠️ MAJEURE | Dans `WaitAsync` : entre `mustWait = false` (hors lock) et l'enqueue du `TaskCompletionSource`, un nouveau fichier prioritaire pourrait être enregistré (race). En pratique atténué car tous les fichiers sont enregistrés avant le démarrage des workers, mais le code est fragile |
| Fonctionne en multi-job parallèle | ✅ OK | Les priorités d'un job bloquent correctement les non-prioritaires des autres jobs |

---

### D. Business software detection

| Point | Statut | Détail |
|---|---|---|
| Pause individuelle de chaque job | ✅ OK (partiel) | Chaque `RunJob` vérifie `_guard.IsRunning()` après chaque fichier et reset son propre `pauseEvent` |
| **Pause non simultanée** | ⚠️ MAJEURE | La détection est réactive, pas pro-active. Un job peut copier encore un fichier complet après la détection du logiciel métier. Pas de mécanisme centralisé de pause immédiate |
| **Auto-reprise absente** | 🔴 CRITIQUE | Après `WaitForResumeAsync(pauseEvent, ct)`, le code check `if (_guard.IsRunning()) break;` — ce qui **rompt le job** si le logiciel est encore là. Il n'existe aucun code qui surveille la fermeture du logiciel métier et appelle `ResumeJobs` automatiquement. L'utilisateur doit déclencher manuellement la reprise |
| Polling raisonnable | ✅ OK | `ProcessBusinessSoftwareGuard` cache le résultat 2 secondes — pas de busy-wait pur |

---

### E. CryptoSoft single-instance

| Point | Statut | Détail |
|---|---|---|
| **Mutex nommé système absent** | 🔴 CRITIQUE | `CryptoSoftEncryptionService.Encrypt()` appelle `Process.Start()` directement, sans Mutex nommé. En parallèle, plusieurs jobs peuvent lancer CryptoSoft simultanément, violant la contrainte single-instance |
| Timeout sur attente CryptoSoft | ❌ N/A | Pas de Mutex → pas de timeout non plus. À implémenter avec `Mutex.WaitOne(timeout)` |

### F. Progress tracking — bug connu

**RÉSOLU** ✅

`BackupService.RunJob` calcule `totalFiles`, `totalSize`, `remainingFiles`, `remainingSize` avant la boucle, et émet un `Notify(BackupState { TotalFiles, RemainingFiles, Progress, ... })` pour chaque fichier traité. La mise à jour est bien fichier par fichier.

| Aucun leak de ressources sur 500 fichiers | 1 job, 500 petits fichiers | Channels non collectés, TCS orphelins dans `_nonPriorityWaiters` |

## 7. Recommandations pour la prochaine session

### Fixes bloquants (avant merge vers master)

1. **[Ewan] Thread-safety Notify** : remplacer `_observers` par `ImmutableArray<IStateObserver>` ou ajouter un `lock` dans `Notify`, `Attach`, `Detach`.

2. **[Ewan] Thread-safety `_pauseEvents`** : remplacer `Dictionary<int, ManualResetEventSlim>` par `ConcurrentDictionary<int, ManualResetEventSlim>` dans `GetPauseEvent`.

3. **[Ewan] Auto-reprise business software** : ajouter un `Task.Run` de polling dans `RunJob` qui surveille `_guard.IsRunning()` et appelle `pauseEvent.Set()` lorsque le logiciel ferme. Le `break` ligne 152 doit devenir une reprise.

4. **[Ethan] maxDegree configurable** : ajouter `AppSettings.MaxParallelWorkersPerJob` (défaut 3) et lire cette valeur dans `BackupJob.Execute`.

5. **[Ewan] CryptoSoft Mutex** : wrapper l'appel `Process.Start` dans `CryptoSoftEncryptionService.Encrypt` avec un `Mutex(false, "Global\\CryptoSoftMutex")` et un timeout configurable (ex. 30 s).

6. **[Ethan] Catch exceptions** : remplacer le `catch (Exception)` ligne 94 par `catch (OperationCanceledException) { throw; } catch (IOException) { failed = true; }` et supprimer les catch vides lignes 80 et 123.

7. **[Ewan] Supprimer `Console.Error.WriteLine`** dans `BackupService` — remplacer par une notification `BackupStatus.Error` via `Notify`.

### Améliorations importantes (prochaine itération)

8. **[Wilfried] Tests priorité 1** : créer `TransferCoordinatorTests.cs` (aucun test sur la nouvelle classe centrale), ajouter tests pause/resume et stop dans `BackupExecutionIntegrationTests`.

9. **[Louison] Tests CLI** : créer `CommandLineParserTests.cs` — `CommandLineParser` gère des formats critiques (`1-3`, `1;3`) avec zéro test.

10. **[Ethan] WaitForPauseAsync** : éviter `Task.Run(() => pauseEvent.Wait(ct))` — risque de saturation thread pool. Envisager un polling async (ex. `Task.Delay(50)` + check) ou `SemaphoreSlim` à la place de `ManualResetEventSlim`.

11. **[Ewan] Interface `IBackupService`** : extraire pour permettre les tests unitaires de la couche Console sans dépendance sur `EasySave.Services`.
